How build.py Makes a Page

walkthrough · skills/show-me/scripts · 0.31.0

You write a small JSON file; build.py turns it into one checked HTML page.

  • The top-level key picks the page: panels, views or flows.
  • Every page goes through check.py, and an ERROR stops the hand-over.
  • Flow pages have their own module, flow.py, because they need layout.

Build

What happens when you run python3 scripts/build.py page.json.

Step 1 / 3
1

The builder reads the spec and picks the page kind.

One key in the spec decides the layout. No other setting does.

  1. build.py:316Reads the JSON file.passes the spec
  2. build.py:321views makes a walkthrough with tabs.passes tab and step HTML
  3. build.py:326flows hands the spec to flow.py.passes map, full-size view, script
  4. build.py:330Anything else is a sheet of lettered panels.passes panel HTML
2

Each panel or step holds exactly one exhibit.

The exhibit key names the drawing. Two keys in one panel stop the build.

build.py:257
def exhibit(item, claim, where, required=True):
    kinds = [k for k in EXHIBITS if k in item]
    if len(kinds) > 1 or (required and not kinds):
        sys.exit(f"{where}: needs exactly one of ...")
3

The builder inlines the CSS and writes one file.

The page needs no other file. Fonts come from Google Fonts; without them the system font shows.

  1. build.py:333Reads assets/sheet.css and puts it in a style tag.passes the page text
  2. build.py:360Writes page.html next to the JSON.passes the file path
  3. build.py:364Runs check.py and exits with its code.passes OK, or ERROR lines
